# Медси Бот — журнал изменений

Короткая история поведения бота для пользователя и следующих моделей.
Карта устройства системы: [docs/SYSTEM_MAP.md](docs/SYSTEM_MAP.md).
Технические точки отката: [docs/GIT_MAP.md](docs/GIT_MAP.md).

**Как читать:** «в Git» означает наличие изменения в ветке, а не новую проверку
живого сервиса. Подтверждение выпуска указывается отдельно. Незавершённая работа
находится только в разделе «Не выпущено». Даты — по Москве.

## Рабочее состояние на 22.10.2026

- **Вход родителей — опубликована новая схема:** вход по сохранённому
  passkey, а при его отсутствии — запрос воспитателю. Убрана выдача доступа только
  по номеру и автоматический вход в первые 30 дней; старые сохранённые сессии
  продолжают приниматься с прежним сроком действия. Новые сессии живут год и привязаны к поколению профиля,
  поэтому выписка/повторное создание профиля отзывает старый доступ. Запрос
  подтверждения связан с секретом устройства и выдаёт сессию один раз. Миграция
  `0015` применена к D1; Worker развёрнут, Pages собраны, основной сайт отвечает
  новым экраном входа. Passkey церемония проверена на генерации
  параметров и тестовых состояниях, но не на физическом телефоне.
- **Проверки локальной auth-пачки:** `npm run verify`, `npm audit --omit=dev`,
  `git diff --check` и Wrangler dry-run прошли. Миграция успешно применена
  локальной Cloudflare-сессией. GitHub migration workflow отклонён Cloudflare
  из-за credentials; отдельно требуется исправить credentials workflow.
- Worker опубликован прямым авторизованным Wrangler-выпуском после того, как
  GitHub Worker workflow был отменён во время публикации. В workflow уже добавили
  установку npm-зависимостей; автоматический повторный выпуск этим путём ещё не
  подтверждён. На физическом устройстве passkey-проход не проверяли.

- **Снизили записи D1:** Worker больше не перезаписывает `report_current`, если
  отчёт и версия не изменились; одинаковая новая дневная публикация сохраняется
  как новое событие. Apps Script пропускает повторную отправку неизменившихся
  отчётов. Изменения отправлены в GitHub, Workers и Pages; сопоставимую статистику
  D1 после короткого интервала ещё предстоит снять.
- **Для уже вошедших родителей:** не показываем предложение подключить passkey
  при восстановлении сессии или после подтверждения воспитателем. Passkey
  предлагается только после новой регистрации. Старые действующие сессии
  продлеваются в фоне, если до истечения осталось меньше 30 дней; при задержке
  Cloudflare запуск панели продолжается без ожидания дольше 2,5 секунды. Это
  сохраняет привычный вход и помогает не довести активную сессию до срока в 30
  дней. Старый токен, уже истёкший до следующего входа, сам продлить нельзя.

- **Перенесли состояния отчётов:** D1 получил отметки прочтения,
  напоминания и журнал однократного импорта; миграции `0013` и `0014` применены,
  Worker API опубликован. Импорт завершён со сверкой версий; Apps Script читает
  прочитанность и сроки напоминаний из D1. Удалены только `REPORT_NOTIFICATION_STATE`
  и `REPORT_INACTIVITY_STATE`; `DATABASE`, `MEDSI_CONTACT_SYNC` и
  `PARENT_ACCESS_REQUESTS` сохранены. Защитили устаревшие helpers от пересоздания
  удалённых листов; guard-патч `20b5821` опубликован, Apps Script web app и Pages
  завершились успешно.
- **Упорядочили Apps Script:** историю отчётов вынесли в `report-history.js`,
  добавили файл в clasp allowlist; штатная публикация Apps Script прошла.
  Алгоритм распределения отчётов не менялся.
- **Экран установки опубликован:** инструкции iPhone/Android, SVG «Поделиться»,
  крестик и «Нет, спасибо» вошли в Pages. Сборка прошла; проверка отдельного
  телефона в этом выпуске не выполнялась.
- **Остаток:** проверить passkey-проход на iPhone/Android. `PARENT_ACCESS_REQUESTS` пока остаётся нужным
  для воспитательского одобрения. Отдельно изучить старую/новую регистрацию и
  совместимость родителей до перехода; завершить архитектурный разбор Apps Script
  и придумать удобное восстановление при потере всех сохранённых ключей.

## Как обновлять журнал

Одна запись на законченную смысловую пачку, обычно 3–6 коротких пунктов:
что добавили/исправили/убрали, зачем, что важно сохранить и статус выпуска.
При переносе из «Не выпущено» указывать дату фактического выпуска и что
подтверждено. Коммит, успешная публикация и живой сценарий — разные отметки.
Не описывать планы как уже работающие функции. Не добавлять данные семей,
секреты, тексты отчётов или длинный технический протокол.

Журнал — обычный Markdown: исполняемый код его не подключает.
