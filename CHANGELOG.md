## Выпущено 22.10.2026 (`c9bd729`) — защита от опоздавших отчётов и короткая блокировка

- Cloudflare принимает пакет отчётов только если его номер версии всё ещё

- После записи отчётов в таблицу сетевые синхронизации запускаются уже без общей
  блокировки. Воспитатель и другие процессы не ждут ответа D1, а повторная
  отправка безопасна благодаря версии публикации.

  production перед выпуском кода. Полный `npm run verify`, GitHub Verify,
  Cloudflare Worker, существующий Apps Script web app и Pages завершились успешно.
- Apps Script workflow подтвердил шаг `Update the existing web application`.
  Timeweb пропущен по просьбе пользователя.
- Сессии родителей, passkey и правила распределения имён не менялись. Список
  фактически установленных Apps Script-триггеров остаётся непроверенным.

## Подготовлено — 22.10.2026 — защита регистрации от поздней синхронизации

- Если выписка происходит после того, как Apps Script уже забрал заявку из
  Cloudflare, отменённая заявка больше не должна восстанавливать строку в
  `REPORTS`. Каждая новая строка помечается служебным ID регистрации в скрытом
  столбце I; Cloudflare подтверждает заявку только пока этот профиль активен.
- Если выписка успела отменить заявку, Apps Script удаляет только строку с её
  служебной меткой. Даже старая сверка без метки не может вернуть недавно
  выписанный профиль. Новая регистрация с новым ID остаётся разрешённой.
- Синтетические сценарии поздней заявки, новой регистрации с тем же номером и
  очистки только помеченной строки прошли. Выпуск ещё не выполнен.

**Как читать:** «в Git» означает наличие изменения в ветке, а не новую проверку
живого сервиса. Подтверждение выпуска указывается отдельно. Незавершённая работа
находится только в разделе «Не выпущено». Даты — по Москве.

## Выпущено — 22.10.2026 — фоновая запись регистрации

- Интерфейс родителя больше не ждёт, пока Apps Script получит общую блокировку

  прохода; повтор не создаёт вторую строку.

  закрытие профиля в D1 быстрое, а очистка `REPORTS`, истории и медиа идёт через
  долговечную очередь с повторами.
- Проверены синтетические гонки и задержка UI: профильная очередь 39/39 тестов,

## Как обновлять журнал

Одна запись на законченную смысловую пачку, обычно 3–6 коротких пунктов:
что добавили/исправили/убрали, зачем, что важно сохранить и статус выпуска.
При переносе из «Не выпущено» указывать дату фактического выпуска и что
подтверждено. Коммит, успешная публикация и живой сценарий — разные отметки.
Не описывать планы как уже работающие функции. Не добавлять данные семей,
секреты, тексты отчётов или длинный технический протокол.

Журнал — обычный Markdown: исполняемый код его не подключает.
