# Защита принадлежности детских отчётов

21.10.2026. Исполняемый код: `apps-script/medsi-bot/Медси бот.js`.

## Причина исправления

Словарь NAME_VARIANTS связывает формы имени, а исходный короткий заголовок
не содержит постоянного идентификатора ребёнка. Раньше регистрация, изменение
REPORTS и минутный таймер заново распределяли старый источник по текущему
списку. После выписки совпадение имени и инициала могло переадресовать старый
блок другому ребёнку. Один прежний тест даже разрешал «Александр И.» → строка
«Александра И.»; теперь он проверяет запрет такого сопоставления.

## Ограничения и защита

1. Противоположные явные формы имени не взаимозаменяемы. Саша/Женя/Валя
   нейтральны; сокращения Катя/Екатерина продолжают сопоставляться.
2. Несколько разных детей с одним именем и инициалом требуют уточнения.
   Уже существующее различение 2–4 буквами фамилии сохранено.
3. `RAW_REPORT_OWNER_<kind>_<fingerprint>` хранит принадлежность блока:
   хеш тела и группы имени → хеш полной идентичности, контакты и эпоха
   поступления. Тело отчёта не сохраняется в этом реестре.
4. Ключ не зависит от сокращения фамилии и отображаемого варианта имени.
   Изменение «Саша Бы.» на «Александра Б.» не передаёт владение другому ребёнку.
5. Регистрация нового контакта в REPORTS создаёт `REPORT_ADMISSION_<phone>`.
   Повторное поступление под тем же номером получает новую эпоху.
6. Владение записывается до выдачи отчёта. Первоначальный запуск принимает
   существующее назначение только при совпадении тела с REPORTS. Пустая новая
   строка не получает неизвестный старый блок автоматически.
7. Неоднозначный блок остаётся заблокированным после выписки одного из детей.
   Уточнение принимается из заново поданного авторского заголовка с фамилией/
   явной формой имени, а не из автоматически сформированного заголовка.
   Уже известный владелец не меняется даже при повторной отправке старого тела.
8. Ещё один родитель того же активного ребёнка получает доступ, пока остаётся
   контакт исходного владельца. Одинаковая короткая подпись без этого недостаточна.
9. Перед записью проверяются телефоны, имена и фамилии в текущих строках.
   Перестановка строк прерывает проход; минутный таймер повторяет распределение.
10. `buildParentReportSnapshot_` дополнительно проверяет владельца при чтении.
    Этот барьер охватывает прямой родительский ответ, D1 current и историю.
    Чужой текст не выдаётся, даже если попал в ячейку из-за параллельной правки.
11. Попытка опубликовать известный чужой блок возвращает ошибку до сохранения
    нового источника. Фоновая блокировка оставляет примечание в исходной ячейке.

Эта защита не определяет достоверность написанных воспитателем фактов и не
угадывает ребёнка по содержанию. Безопасный результат неоднозначности — отсутствие
отчёта и запрос уточнения. Две полностью одинаковые личности с теми же контактами,
внесённые вручную без цикла регистрации, требуют отдельного идентификатора
поступления в справочнике: короткое имя само по себе такого различия не содержит.

Реестр принадлежности нельзя очищать при обычном обновлении справочника: это
защита от повторного использования старого текста. Удаление данных пациента
по отдельному поручению должно учитывать и эти Script Properties. Записи
содержат хеши и контакты, но не клинические тексты. При нехватке места/сбое
PropertiesService выдача останавливается; обход по короткому имени запрещён.

## Проверки

`npm run verify` включает синтетические случаи одновременных Саш Б, противоположных
форм имени, выписки/нового поступления, сокращения фамилии, смены порядка строк,
нового родителя того же ребёнка, повторного поступления под тем же телефоном,
неизвестного старого блока и последнего барьера родительского чтения.
Производственные сообщения для тестов не отправляются; реальные отчёты в Git
не добавляются. Проверку выпуска фиксировать отдельно от локальных тестов.
