# События вместо минутной пересборки — 22 октября 2026

Этот этап дополняет прежний архитектурный аудит: общая функция распределения
сама по себе не устраняла повторные запуски. Прежняя формулировка «план закрыт»
не доказывала отсутствия повторного расчёта.

## Что изменено

- Веб-отправка уже вызывала `appendReport` напрямую, минуя ограничение onEdit.
  Этот путь сохранён для утреннего, вечернего и группового отчёта.
- Установленный `onReportsD1Edit` сразу обрабатывает A1 источников; изменения
  NAME_VARIANTS сбрасывают словарь текущего выполнения и вызывают обслуживание
  без новой публикации. Изменения существенных столбцов REPORTS запускают
  перерасчёт, если lifecycle уже не выполнил его сам. Структурный onChange
  сохранён; обычный EDIT не обрабатывается дважды.
- Новый `runScheduledMedsiMaintenance` объединяет бывшие таймеры распределения
  и полной сверки в один запуск каждые 10 минут. Тяжёлая страховка работает
  только 07:00–23:59 Europe/Moscow. Google всё равно покажет короткий ночной
  запуск таймера, который сразу возвращает `night`; ночью полной сверки нет.
- Старые CLOCK-триггеры `distributeChildReports` и `syncD1ProfilesFromReports`
  автоматически заменяются. Контакты и установленные edit/change не удаляются.
  Одноразовое переключение выполняет существующий минутный обработчик очереди
  либо ближайший старый таймер; отдельное ручное действие владельца не нужно.
- Перед полным расчётом сравниваются хеши raw, существенных полей REPORTS,
  NAME_VARIANTS и реестра принадлежности. Повтор без изменений не разбирает
  блоки и не перезаписывает E/F. Значения одинакового столбца не записываются
  даже при осмысленном новом запуске. Явная публикация идентичного текста
  всё ещё разрешена: новый дневной отчёт может повторять вчерашний.

## Почему не теряются нужные повторы

После записи локальный результат и доставка в Cloudflare имеют разные состояния.
Незавершённая передача хранится как request/ack; старое завершение не стирает
новое задание. Сбой доставки не требует новой отправки raw или полного расчёта.
Короткая отметка исполнения не допускает одновременную отправку одного задания;
сетевых вызовов внутри блокировки таблицы нет. Отложенные напоминания сверяют ID
поступления, чтобы старый запрос не затронул новую семью с тем же телефоном.

Существующий минутный `retryPendingReportsD1ProfileSync` оставлен **для реальных
незавершённых регистраций/сверок/передач**, в том числе ночью. Без задания он
читает служебные отметки и выходит; полное распределение он не запускает.
Отключать его вместе со старым минутным распределением нельзя.

Один пакет D1 больше не строится целиком заново для каждого вида публикации:
обычный случай использует один снимок, несколько публикаций — снимки нужных видов.
Проверки принадлежности, текущего состава и исходного текста перед записью
сохранены. Чекпоинт дополнительно защищён от изменения raw во время его расчёта.

## Границы проверки

Полный npm run verify и целевые синтетические сценарии покрывают неизменный
повтор, явную одинаковую публикацию, изменения словаря/семей, ночное расписание,
сетевые ошибки, одновременную передачу, позднее подтверждение и смену поступления.
Реальные отчёты для теста не заменялись; тестовая рассылка семьям не выполнялась.
Изменён только Apps Script и документация/проверки; Cloudflare и сессии не менялись.

Проверка списка живых запусков через Google API вернула 403; просмотр кабинета
недоступен из-за ошибки захвата экрана macOS. Поэтому тест перехода расписания
и успешный выпуск кода нельзя выдавать за ручную сверку реально установленных
триггеров. Автоматическое переключение предусмотрено в действующем retry-handler.
Снижение реальных затрат и скорость в секундах пока не измерены.
