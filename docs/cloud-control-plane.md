# Облачный контур Медси Бота

## Назначение компонентов

| Компонент | Где работает | За что отвечает |
| --- | --- | --- |
| Веб-интерфейс и gateway | Timeweb | Панели родителей, воспитателей и психологов; статические файлы, проксирование и S3-медиа |
| `medsi-chat-worker` | Cloudflare Worker + D1 + KV | Чаты, вложения, сессии D1, снапшоты и фоновые задачи |
| `medsi-chat-gateway` | Cloudflare Worker | Узкий service-binding прокси к основному чат-Worker |
| `medsi-push-worker` | Cloudflare Worker + KV | Web Push-подписки и уведомления |
| Apps Script и Google Sheets | Google | Распределение отчётов, таблица, авторизация и фоновая синхронизация с Cloudflare |

## Где находятся исходники и как их синхронизировать

GitHub хранит копии исходников Timeweb, Apps Script и Cloudflare Workers. Для
Apps Script и Workers GitHub больше не отправляет код в production автоматически
и не забирает изменения обратно. После прямого изменения на платформе обновляй
соответствующую копию в репозитории вручную, только после сравнения с реально
опубликованной версией.

Перед изменением Apps Script:

1. Проверь текущую версию активной веб-публикации.
2. Получи текущий исходник проекта через `clasp pull` после проверки локальных
   изменений и сохранения нужных правок.
3. Сравни исходник с `apps-script/medsi-bot/` в `timeweb-next`.
4. Если опубликованную версию нельзя сопоставить с исходником, не считай GitHub
   копию точной и сообщи об ограничении.

Перед изменением Worker:

1. Проверь активную версию и bindings через Wrangler.
2. Сравни конфигурацию и исходники в `services/cloudflare/` с production.
3. Если точный опубликованный исходник получить нельзя, явно отметь это и не
   перезаписывай GitHub-копию вслепую.

Не печатай секреты, токены, Script ID, deployment ID, данные таблиц или
персональные данные в логи, коммиты и отчёты.

## Публикация

1. Push в `timeweb-next` запускает Timeweb webhook и штатную GitHub Pages
   публикацию сайта. Проверки исходников запускаются через `verify.yml`.
2. Apps Script редактируется и публикуется непосредственно в Google или через
   авторизованный локальный `clasp`. После этого GitHub-копию обновляют вручную.
   GitHub Actions не синхронизируют и не публикуют Apps Script.
3. Cloudflare Workers редактируются и публикуются непосредственно через
   Cloudflare Dashboard или Wrangler. После этого GitHub-копию обновляют вручную.
   GitHub Actions не публикуют Worker-код.
4. D1 migrations остаются отдельной ручной операцией через `deploy-cloudflare.yml`
   в защищённом окружении `cloudflare-production`; для запуска нужны явное
   подтверждение и reviewer.

Удалённые workflow и их прежние настройки не удаляют уже созданные GitHub
Secrets и Environments. Неиспользуемые секреты владелец может удалить отдельно;
Cloudflare secrets, необходимые для D1-миграций, нужно сохранить.
