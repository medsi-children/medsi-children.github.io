# Медси Бот — план production-переезда

Статус: ПОДГОТОВКА. Никакая миграция данных, DNS или удаление Cloudflare-ресурсов этим документом не запускается.

## Финальная архитектура

- Timeweb Node.js: production web/gateway для родительской, воспитательской и psychology-панелей.
- Timeweb S3: все новые и мигрированные фото/видео чатов.
- Cloudflare D1: сообщения, реакции, read/unread, pin и история чатов.
- Cloudflare Push Worker: оставить как отдельный работающий push-сервис.
- Apps Script + Google Sheets/Drive: отчёты и текущий production до момента cutover; таблица остаётся источником актуальной истории чатов до разовой миграции в D1.
- GitHub: исходный код и автодеплой Timeweb, не production-хостинг.

## Публичные адреса после cutover

- `/` — родительская панель.
- `/tutors` — воспитательская панель.
- `/psychology` — отдельная панель психологов.
- Старые `/tutors.html` и `/psychology.html` оставить рабочими для совместимости старых закладок.

## До запуска миграции

1. Закончить косметический проход по всем трём интерфейсам.
2. Зафиксировать последний стабильный commit `timeweb-next` как release candidate.
3. Проверить Timeweb health, S3, session service и Cloudflare chat upstream.
4. Снять инвентаризацию актуальной таблицы сообщений и всех fileId/Drive/KV/S3 вложений.
5. Снять инвентаризацию D1 и вычислить разницу с production-таблицей.
6. Подготовить резервный экспорт таблицы сообщений и список медиа до любых записей.

## Разовая миграция

Порядок важен:

1. Включить короткое окно миграции, чтобы новые сообщения не расходились между таблицей и D1.
2. Перенести актуальные сообщения из production-таблицы в Cloudflare D1 с сохранением времени, стороны, текста, реакций, reply-связей и статусов, где они доступны.
3. Перенести старые вложения из Google Drive/Cloudflare KV в Timeweb S3.
4. Обновить fileId соответствующих сообщений в D1 на `s3:<key>`.
5. Сверить количество сообщений, чатов и вложений источник ↔ D1/S3.
6. Проверить выборочно старые и новые сообщения/фото/видео.

Старые копии файлов НЕ удалять на этом этапе.

## Cutover домена

1. Привязать `медси-бот.рф` к Timeweb-приложению.
2. Проверить HTTPS.
3. Проверить `/`, `/tutors`, `/psychology` на production-домене.
4. Убедиться, что старые воспитательские сессии корректно переиздаются в новый Timeweb chat-session flow.
5. Провести короткий smoke test:
   - родитель: вход → отчёт → чат → сообщение → фото;
   - воспитатель: вход → список чатов → ответ → фото;
   - psychology: отправка тестового отчёта;
   - push: одно уведомление родителю/воспитателю.

## После стабильного запуска

Не чистить старую инфраструктуру сразу. Выдержать стабильную работу production, затем удалить только подтверждённо неиспользуемое.

Оставить в Cloudflare:
- D1 production;
- Push Worker;
- chat Worker/API, пока Timeweb gateway использует его;
- любые bindings, которые реально нужны этим сервисам.

Кандидаты на удаление только после проверки зависимостей:
- старые UI Workers;
- экспериментальные upload Workers;
- временные custom subdomains;
- KV media после подтверждения полной миграции в S3;
- старые тестовые маршруты/диагностика.

## Rollback

До очистки старой инфраструктуры rollback должен оставаться простым:
- вернуть DNS production-домена на прежний frontend;
- оставить Apps Script/таблицу и старые медиа нетронутыми;
- не удалять исходные сообщения/вложения до завершения контрольного периода.
